# B1.2 report — adjustments by kind and section, production fee, countries, messages

Prompt: `docs/prompts/29-filmbill-B1.2-adjustments-fee-country-messages.md`. Built 2026-11-25.

**In plain words.** A discount can now be limited to one section (or
sub-section) and to certain kinds — "Equipment discount" and "Crew discount"
are one click. The production fee has its own control on every budget, starts
from a company preset that you set once, and each extra can say whether the
fee falls on it. Countries are picked from one list everywhere ("Austria
(AUT)"), and the tax messages now say whose country is missing and where to
set it.

**The 2b design decision (reported before building).** Shape (a): one
pure-engine concept. An `Adjustment` may carry an opaque `role`; a `Line` may
list roles it is `exempt_from`. For an adjustment with a role, an exempt
line's net leaves the base and its tax category's weight — for the
`subtotal` and `subtotal_incl_previous` bases by subtraction, for `kinds` by
skipping the line. Nothing else changes and there is no second calculation
path. The budget maps an unticked extra to `exempt_from: ["production_fee"]`.
Golden fixtures `role-exempt-line` and `role-exempt-kinds-fee`.

## Defaults I chose

- **No default production fee** (NULL); the S1 example's own 8 % is marked as
  its fee and the preset never touches it. Fee rows of example budgets made
  before 0019 are **not** marked (a label is not proof); their "Production
  fee" stays an ordinary surcharge in the Adjustments panel.
- The fee is limited to **0–100 %**; a kinds fee is `base = "kinds"`, an
  all-kinds fee `base = "subtotal"`. Switching the fee off retires the row;
  on again makes a new one.
- The preset is read and written under **`company.settings.edit`** (owner,
  admin) on its own endpoint, so Staff never see it through `GET /company`.
- Crew quick-add = `labor`; the base of a document-level kind filter is the
  lines' own nets (Crew discount on S1 takes 5 % of 4,200.00, not 3,990.00).
- The Extras section is not offered in "Applies to".
- **Kosovo (XK / XKX)** is in the country list (IBAN lengths use it); EL and
  XI are not. Tax-identifier countries are not validated against the list.
- **No country migration**: every write path already upper-cased through the
  schemas; codes not in the list stay as stored and show "(unknown code)".
- Names come from the data file, not `Intl.DisplayNames` (so no fallback is
  needed). The web copy of the list is a checked mirror because the web image
  does not contain the API's files.
- Rule 11 vs the prompt's "grep the web sources": the scan is kept as a guard
  against a *new* free-text field (comments stripped, with a probe); the
  proof that the existing fields work is behavioural (each screen's test picks
  a country and checks what is sent or shown).
