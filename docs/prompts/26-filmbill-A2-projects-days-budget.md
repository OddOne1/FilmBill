## Part 1 — data model and API for projects and days (migration, rule 9)

- `projects`: `id`, `company_id`, `project_number` (number series `project`, default `PRJ-{YYYY}-{SEQ}`, yearly reset, padding 3, seeded for new companies and backfilled for existing ones), `name`, `client_party_id` (nullable, a party of the same company), `description`, `status` (`planning` | `active` | `wrapped` | `archived`), `start_date`, `end_date` (nullable), `notes`, timestamps. Number allocated inside the creating transaction.
- `project_days` (SCOPE §11.3): `project_id`, `date`, `type` (`prep|shoot|travel|wrap|post|office|off`), `location`, `call_time`, `wrap_time`, `notes`. Unique `(project_id, date, type)`. A range endpoint `POST /projects/{id}/days/range` `{from, to, type, skip_weekends?}` creates days in one transaction and reports what it created and what already existed.
- **Permissions (new keys, list them in the report):** `projects.view`, `projects.edit`. Defaults [Guessing]: view = owner, admin, accountant, producer, staff; edit = owner, admin, producer. Another company's data is 404.
- **Audit** (caller's transaction, diffs): `project.created|updated|status_changed`, `project_day.created|updated|removed` (range creation is one event with counts). Days may be removed (they are plans, not records); removal is audited.
- **Reference guard:** a party referenced by a non-archived project cannot be archived (409 naming the project); register through the P1b archive guard/reference registry.
- Endpoints: `GET/POST /projects`, `GET/PATCH /projects/{id}`, status change, days sub-resource and range, search/filter by status and client. Regenerate `api.gen.ts`.

## Part 2 — the Budget (migration, rule 9), built on A1's engine, draft-only (D72)
No number, finalize, PDF or ledger anywhere in this part.
- `budgets`: `project_id`, `name`, `currency` (company currency only), `notes`, `is_active`, `locked_at` (nullable; a locked budget rejects line, section, global and adjustment edits with 409 and a sentence; unlocking is an audited action; locking is how an approved estimate is frozen before Committed/Actual exist). A project may have several budgets (scenarios); one may be marked `is_primary`.
- `budget_sections`: `budget_id`, `code` (user-visible account number, e.g. `1100`), `name`, `parent_id`, `position`. **Maximum depth 2**, matching the engine's group limit (SCOPE §5.4); a third level is refused with a readable sentence naming the engine limit.
- `budget_lines`: `section_id`, `position`, `item_id` (nullable; free-text lines allowed), `description`, `kind` (system enum; from the item when set), `quantity`, `quantity_ref`, `period_value`, `period_ref`, `period_unit`, `factor`, `factor_source` (`manual` | `catalog`), `unit_price`, `unit_cost`, `discount_mode` (`percent` | `amount` | null) and `discount_value`, `tax_ref` (from the item's default tax class, for grouping only), `tags` (array), `allow_negative`, `notes`. **Rates are copied from the catalog at insertion** (bill rate to `unit_price`, cost rate to `unit_cost`, for the line's period unit) and stay editable; a line keeps `item_id` and the API flags "differs from catalog" without changing anything. When `factor_source = catalog` and the item has a rental factor group, the factor is `factor_for(group, period_value)` from A1, resolved **before** the engine call, and the response includes `explain_factor`'s explanation.
- `budget_globals` (closed vocabulary, **no expression language**): `key` (slug, unique per budget), `label`, `value NUMERIC(18,4)`, `unit`, `source` (`manual` | `days:<type>`). A global with source `days:shoot` has its value **computed from the project's days of that type** (count of days) and is read-only in the UI. A line's `quantity_ref`/`period_ref` names a global key; refs are resolved to plain numbers in the service **before** the engine is called; a dangling ref is a 422 naming the key. Deleting a global that a line references is refused (409 naming the lines); globals may be deactivated only when unreferenced.
- `budget_adjustments`: `budget_id`, `section_id` (nullable = document level), `position`, `label`, `type`, `mode`, `value`, `base` (as the engine's adjustment contract from Step 0).
- **Calculated view:** `GET /budgets/{id}/calculated` builds the engine input from the stored rows (reusing `/calc/preview`'s mapping), calls `billing/calc`, and returns per-section and per-line `price`, `cost`, `margin`, `margin_percent`, the **top sheet** (sections with price/cost/margin/share of total), document totals, net per tax_ref, factor explanations and the engine's warnings. **The web never computes money.** No VAT in budgets: net only.
- Operations: add/move/reorder/duplicate lines and sections (`position` handled server-side), `POST /budgets/{id}/duplicate` (copies sections, lines, globals, adjustments into a new budget named "… (copy)", unlocked), `POST /projects/{id}/budgets/example` creating a budget named **"Example (S1)"** from the SCOPE §12 S1 quote data so the totals can be checked by eye (labelled as an example in its notes; permission `budgets.edit`; sections and lines as in A1's S1 fixture, with the unit costs that fixture uses).
- **CSV in/out:** `GET /budgets/{id}/export.csv` (sections, lines, computed price/cost/margin, German-friendly UTF-8 with BOM) and a line import with the same plan→apply pattern as A1's catalog import (`/import/preview`, `/import`, applies exactly what the preview showed, per-row sentences, never deletes, unknown section code is an error not an invention, German decimal comma accepted).
- **Permissions (new keys, list them in the report):** `budgets.view` (includes cost and margin) and `budgets.edit`. Defaults [Guessing]: view = owner, admin, accountant, producer; edit = owner, admin, producer. **Staff have neither**, because the sheet exposes cost rates and margin; a later slice adds crew-safe views. Tests assert that a staff user gets no cost or margin field from any budget endpoint.
- **Audit** (caller's transaction, diffs): `budget.created|updated|duplicated|locked|unlocked|set_primary`, `budget_section.*`, `budget_line.created|updated|removed|moved`, `budget_global.*`, `budget_adjustment.*`, `budget.import_applied` (counts). Bulk operations write one event with counts, not hundreds.
Tests (real Postgres, declared): migration up/down; position handling under concurrent inserts; depth-3 refused; ref resolution and the dangling-ref/referenced-global guards; `days:shoot` global changes when a shoot day is added or removed and the calculated numbers follow; catalog factor resolution with the explanation; **the example budget's calculated net equals 12,517.20 and its cost, margin and top-sheet shares equal what the A1 S1 fixture says**; lock/unlock behaviour; duplicate equals original numerically; CSV round trip (export, import into a fresh budget, identical totals); import preview equals applied result; the permission and isolation matrix including the staff no-cost assertion; no-DELETE assertion.
**Mutations, a real FAIL line each, rows chosen so only that guard protects them:** resolve a ref after the engine call instead of before; a locked budget accepts a line edit; staff response includes `cost`; a global referenced by a line can be removed; the example creator rounds a section instead of each line; import applies something different from its preview.
