## Part 1 — the link (model, API, audit)
- Migration: `parties.user_id` nullable FK to `users.id` (`ON DELETE SET NULL`). **At most one active contact per user per company, and at most one user per contact** (partial unique indexes on `(company_id, user_id)` where `user_id IS NOT NULL`). A link is only allowed to a person-type contact and only when that user has an **active membership in the same company** (a revoked or expired membership is refused with a clear message).
- **Never merge or rewrite contacts.** Linking only sets `user_id` (and `is_crew` when asked). Existing roles, assignments, tags, tax data on the contact stay as they are.
- API (company scoped; missing permission answers 404):
  - `GET /team` — the company's active members with: name, email, membership role, **crew state** (`not_crew | crew | needs_link`), the linked contact (id, name) if any, and a **suggested contact** if no link exists and exactly one person contact has the same primary email (case-insensitive). If two or more match, no suggestion, the admin picks by hand.
  - `POST /team/{user_id}/crew` (admin) — body: `mode` = `link` (with `party_id`, the admin confirmed it) or `create` (a new person contact is made from the login's first and last name, the login email as primary email contact point, `is_crew = true`, tag "Team"); sets `user_id` and `is_crew = true`. Response includes the contact.
  - `DELETE /team/{user_id}/crew` (admin) — "stops working as crew": `is_crew = false`, link kept. The response lists **future bookings** of that person (booked or scheduled) so the web can say so; nothing is cancelled automatically, and nothing is deleted.
  - `POST /team/{user_id}/unlink` (admin) — removes the link (`user_id = null`), contact stays.
  - **Self-service (any active member, own login only, no `parties.view` needed):** `GET /me/crew` (am I crew, my roles with confirmed/self-reported, my linked contact name), `PUT /me/crew` (switch on/off), `PUT /me/crew/roles` (the list of labor items I can do; **no rates in the request or response**), `GET /me/schedule` (below). Switching on when no contact is linked: if **no** contact has my email, create a new crew contact exactly as `mode = create`; if **one or more** do, **do not create or link anything**: answer with the sentence "A contact with your email already exists. An admin has to connect it to your login." and, if Step 0 item 4 is yes, create one notification for the company's admins ("<name> wants to work as crew; connect their contact in Team"); if no, only the sentence. A member can never touch another member's contact through these routes (the id comes from the session, never from the request).
- **Roles and "self-reported":** add `confirmed bool default true` and `set_by` (`admin | self`) to `party_crew_roles`. Roles written through `/me/crew/roles` are `confirmed = false, set_by = self`; an admin saving or ticking **Confirm** makes them confirmed. Removing a role by the member is allowed. A member can neither read nor change `own_day_rate` for themselves; the admin path is unchanged.
- Audit: `team.crew_linked`, `team.crew_created`, `team.crew_stopped`, `team.unlinked`, `crew_role.self_set`, `crew_role.confirmed`; self-service entries record the actor and that it was self-service.
- Revoked or deactivated login: the link stays (history), the contact stays crew; `GET /team` shows "no active login"; `/me/*` obviously does not apply.
