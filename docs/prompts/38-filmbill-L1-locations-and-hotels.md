## Part 1 — the record (model, API, audit)
- Migration, company-scoped, soft deletion only (`is_active`; a location in use may be archived and keeps showing on what already uses it, marked "archived"). Table `locations`:
  - `name` (required, unique among active rows per company, case-insensitive), `kind` = `shoot | hotel | hospital | other`,
  - address: `street`, `street2`, `zip`, `city`, `country` (alpha-2 stored, shown as the dropdown of B1.2),
  - `latitude`, `longitude` (Decimal, both or neither, ranges -90..90 and -180..180),
  - `phone`, `email`, `website` (plain text, validated lightly), `emergency_phone` (hospital),
  - `access_notes` (parking, entrances, gate codes are NOT to be stored here: say so in the helper text), `notes`,
  - `contact_party_id` nullable (an on-site contact from Contacts, optional) plus `contact_text` free text ("Frau Berger, Hausmeister, 0664 …"),
  - for `hospital`: `verified_on` (date), `verified_by` (user), `verification_note`. **Any change to the address, coordinates, phone or emergency phone of a verified hospital clears the verification** (and says so in the response and the audit entry); changing notes does not.
  - timestamps.
- **Pure module** `billing/planning/map_links.py` (no SQLAlchemy, no FastAPI, same import-boundary test as the other pure modules, a second test proving the probe can fail): `map_link(location)` and `directions_link(origin, destination)` building `https://www.google.com/maps/search/?api=1&query=…` and `https://www.google.com/maps/dir/?api=1&origin=…&destination=…` from coordinates when both exist, else from the URL-encoded address, else `None`. No key, no network, no account. Also `parse_coordinates(text)` accepting "48.2082, 16.3738", "48.2082 16.3738" and "48.2082;16.3738" with comma decimals tolerated, returning a pair or a clear refusal. Golden cases as data (state every number): the three formats, a swapped/invalid range, a missing half, an address with umlauts and spaces, an address with only a city, and the empty location.
- API: list (search, kind filter, "show archived"), create, update, archive/restore, **mark verified** (hospital only: sets the user, today's date, optional note), read with the **links** computed server-side. `GET /locations/{id}/usage` lists where it is used (strips, days, crew assignments with project names) so archiving can tell the user. Audit: `location.created|updated|archived|restored|verified|verification_cleared`.
- **Permissions:** `locations.view` for everyone who can see projects (staff included) **except** kind `hotel`, which needs the same permission that lets a role see crew today (a hotel reveals where a crew member sleeps; D111). `locations.edit`: owner, admin, producer.
